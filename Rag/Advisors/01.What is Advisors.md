# 📚 Spring AI Advisors

> **Advisors** are one of the most powerful features of Spring AI. They act as middleware between your application and the Large Language Model (LLM), allowing you to intercept, modify, monitor, or even block AI requests and responses without changing your business logic.

# 🤔 What are Advisors?

An **Advisor** is a lightweight interceptor that executes **before** and **after** an AI model call.

Think of it exactly like a **Spring AOP interceptor**, but instead of intercepting method calls, it intercepts **AI conversations**.

Without changing your application code, Advisors can:

- Modify prompts
- Add conversation history
- Inject company documents
- Log requests
- Validate user input
- Block unsafe prompts
- Modify AI responses
- Store execution data
- Measure performance

Simply put,

> **Advisors are middleware for AI interactions.**

# 🎯 Why Advisors?

Spring AI introduces Advisors to solve common enterprise AI challenges.

## 1. Centralized Control

Advisors provide one central place to control AI behavior.

Examples:

- Block harmful prompts
- Filter sensitive information
- Modify AI responses
- Enforce business rules

Instead of adding these checks everywhere, they are written once inside an Advisor.

---

## 2. Cross-Cutting Concerns

Many tasks are required for every AI request.

Examples include:

- Logging
- Monitoring
- Retry logic
- Performance tracking
- Exception handling

Without Advisors, every service would duplicate this code.

With Advisors, these concerns are implemented once and reused everywhere.

---

## 3. Dynamic Prompt Engineering

Sometimes prompts must change depending on:

- Logged-in user
- User role
- Department
- Language
- Current application state
- Security policies

Advisors can automatically enrich or rewrite prompts before they reach the LLM.

Example:

User asks:

```
Generate today's sales report.
```

Advisor modifies it to:

```
You are a finance assistant.

Current User:
Manager

Department:
Sales

Generate today's sales report.
```

The user never sees this modification.

---

## 4. Enterprise Governance

Large organizations require governance.

Advisors help enforce:

- Access control
- Compliance rules
- Audit logs
- Cost optimization
- Rate limiting
- Security policies

This makes AI applications suitable for production environments.

---

## 5. Extensibility

Advisors keep the architecture flexible.

You can:

- Add new Advisors
- Remove Advisors
- Replace Advisors
- Chain multiple Advisors

without changing your business code.

# 🔄 How Advisor Chain Works

## Step 1

The application creates a `Prompt`.

---

## Step 2

Spring AI converts it into a

```
ChatClientRequest
```

along with an empty **advisor context**.

---

## Step 3

Each Advisor processes the request.

It may:

- Read prompt
- Modify prompt
- Add data
- Store information
- Block request

---

## Step 4

The last Advisor sends the request to the LLM.

---

## Step 5

The LLM generates a response.

---

## Step 6

Spring converts it into

```
ChatClientResponse
```

---

## Step 7

Each Advisor processes the response in reverse order.

They may:

- Modify response
- Log response
- Store metrics
- Remove sensitive data

---

## Step 8

Final response is returned to the application.

# 🧠 Why Prompt Augmentation?

A prompt often needs additional information.

There are two major types.

## 1. Your Own Data

LLMs only know what they were trained on.

They do not know:

- Company policies
- Product manuals
- Internal documents
- Research papers

Advisors automatically retrieve this information and append it to the prompt.

---

## 2. Conversation History

LLMs are **stateless**.

Every request is independent.

Example:

User:

```
My name is John.
```

Later:

```
What is my name?
```

Without memory:

```
I don't know.
```

Advisors automatically attach previous messages so the model remembers the conversation.

# 📝 Registering Advisors

Spring AI provides two ways to register Advisors.

---

# 1. Default Advisors

Registered when building the `ChatClient`.

```java
this.chatClient = chatClientBuilder
        .defaultAdvisors(new SimpleLoggerAdvisor())
        .build();
```

Every request automatically uses this Advisor.

No additional code is needed.

---

## When to Use Default Advisors

Use them for functionality required on every request.

Examples:

- Logging
- Memory
- Safety
- Compliance
- Standard prompt enrichment

---

# 2. Per-Call Advisors

Registered only for one request.

```java
chatClient.prompt()
        .advisors(new SimpleLoggerAdvisor())
        .user(text)
        .call()
        .content();
```

Only this request uses the Advisor.

---

## Passing Runtime Parameters

Sometimes an Advisor needs request-specific data.

Example:

Conversation ID

```java
chatClient.prompt()
    .advisors(a -> a.param("conversationId","678"))
    .user(text)
    .call()
    .content();
```

Notice:

The Advisor already exists.

Only its input changes.

---

# Default vs Per-Call Advisors

| Feature | Default Advisor | Per-Call Advisor |
|----------|-----------------|------------------|
| Registered once | ✅ | ❌ |
| Runs for every request | ✅ | ❌ |
| Request-specific | ❌ | ✅ |
| Best for logging | ✅ | ❌ |
| Best for memory | ✅ | ❌ |
| Best for runtime parameters | ❌ | ✅ |

# Important Advisor Methods

## adviseCall()

Used for normal requests.

Typical responsibilities:

- Read prompt
- Modify prompt
- Invoke next advisor
- Modify response
- Throw exceptions

---

## adviseStream()

Used for streaming responses.

Works similarly to `adviseCall()` but processes streamed output.

---

## getOrder()

Determines execution order.

Lower value

↓

Higher priority

Example:

```java
@Override
public int getOrder() {
    return 0;
}
```

---

## getName()

Returns Advisor name.

Useful for:

- Logging
- Debugging
- Diagnostics

---

# 📊 Advisor Execution Order

Order is determined by `getOrder()`.

Lower numbers execute first.

Example:

```text
Advisor A -> Order = 1

Advisor B -> Order = 5

Advisor C -> Order = 10
```

Execution:

```
A
↓

B
↓

C
↓

LLM
```

Response:

```
LLM

↓

C

↓

B

↓

A
```

---

# Request vs Response Order

| Request | Response |
|----------|----------|
| A | C |
| B | B |
| C | A |

The first Advisor processes the request first but the response last.

Think of it like pushing and popping from a stack.

---

# Ordered Interface

Spring provides two constants.

```java
Ordered.HIGHEST_PRECEDENCE
```

Runs first.

Equivalent to

```
Integer.MIN_VALUE
```

---

```java
Ordered.LOWEST_PRECEDENCE
```

Runs last.

Equivalent to

```
Integer.MAX_VALUE
```

---

## Important Notes

Lower number

↓

Higher priority

Higher number

↓

Lower priority

If two Advisors have the same order,

Spring **does not guarantee** which one executes first.

# Built-in Advisors

Spring AI already provides several Advisors.

## 1. SimpleLoggerAdvisor

Purpose:

Logs every request and response.

Useful for:

- Debugging
- Development
- Monitoring

---

## 2. SafeGuardAdvisor

Purpose:

Blocks prompts containing sensitive or forbidden words.

Example:

User:

```
Generate harmful content...
```

Advisor blocks the request before it reaches the LLM.

---

## 3. MessageChatMemoryAdvisor

Purpose:

Automatically adds previous conversation history.

Useful because LLMs are stateless.

Note:

Some AI models may not support message-based memory.

---

## 4. QuestionAnswerAdvisor

Implements **Naive RAG**.

Flow:

```
Question

↓

Search Vector Store

↓

Append Documents

↓

LLM

↓

Answer
```

Simple and easy for basic RAG applications.

---

## 5. RetrievalAugmentationAdvisor

Implements **Modular RAG**.

Supports:

- Query rewriting
- Query expansion
- Custom retrievers
- Custom transformers
- Custom augmentation

Provides much greater flexibility than `QuestionAnswerAdvisor`.

---

# 📝 Best Practices

- Register common Advisors using `defaultAdvisors()`.
- Use per-call Advisors only when needed.
- Pass runtime data using `.advisors()`.
- Assign unique `getOrder()` values.
- Keep Advisors focused on one responsibility.
- Use built-in Advisors whenever possible.
- Create custom Advisors only for business-specific logic.

---

# 🧠 Quick Revision

- Advisors are middleware for AI interactions.
- They intercept requests before and after the LLM call.
- They work similarly to Spring AOP interceptors.
- They centralize logging, security, memory, and prompt enrichment.
- Requests move through Advisors before reaching the LLM.
- Responses move back through the Advisors in reverse order.
- Default Advisors run for every request.
- Per-call Advisors run only for specific requests.
- `getOrder()` controls execution order.
- Lower order values execute first.
- The first Advisor processes the request first but the response last.
- Spring AI provides SimpleLoggerAdvisor, SafeGuardAdvisor, MessageChatMemoryAdvisor, QuestionAnswerAdvisor, and RetrievalAugmentationAdvisor.

# 🔥 Summary

Spring AI Advisors are reusable middleware components that intercept AI requests and responses, allowing developers to implement logging, safety, memory, prompt enrichment, governance, and custom business logic without modifying application code. They operate in an ordered chain around every LLM call, making AI applications modular, maintainable, and suitable for enterprise environments. By supporting both default and per-call registration, Advisors provide a flexible mechanism to build secure, scalable, and production-ready AI systems.
