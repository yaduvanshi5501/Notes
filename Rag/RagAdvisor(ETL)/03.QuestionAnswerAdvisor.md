# 📝 Summary

`QuestionAnswerAdvisor` is Spring AI's built-in implementation of the **Naive Retrieval-Augmented Generation (RAG)** pattern. Instead of manually writing retrieval logic, it automatically performs vector search, retrieves relevant documents, injects them into the prompt, and sends the enriched prompt to the LLM. This significantly reduces boilerplate code and allows developers to focus on business logic rather than RAG infrastructure.

---

## Why QuestionAnswerAdvisor?

Without `QuestionAnswerAdvisor`, a RAG application must manually:

- Generate embeddings for the user's question.
- Perform similarity search on the VectorStore.
- Retrieve the most relevant document chunks.
- Build a prompt containing the retrieved context.
- Control context window size.
- Send the enriched prompt to the LLM.

`QuestionAnswerAdvisor` automates this entire workflow with a single advisor.

---

## Internal Workflow

Whenever a user asks a question, the advisor automatically executes the complete RAG pipeline.

```text
User Question
      ↓
QuestionAnswerAdvisor
      ↓
Generate Query Embedding
      ↓
Similarity Search
      ↓
Retrieve Top-K Documents
      ↓
Inject Context into Prompt
      ↓
LLM
      ↓
Grounded Answer
```

Developers never need to manually build prompts containing retrieved documents.

---

## Advisor Responsibilities

`QuestionAnswerAdvisor` performs four major tasks automatically:

- Retrieves semantically similar documents from the VectorStore.
- Builds an augmented system prompt.
- Sends the enriched prompt to the LLM.
- Stores retrieved documents inside `RETRIEVED_DOCUMENTS` metadata for citations.

---

## Default Behaviour

Without any configuration, the advisor:

- Retrieves the **Top 4** most similar document chunks.
- Uses the configured VectorStore for similarity search.
- Automatically injects retrieved context into the prompt.
- Requires no manual prompt engineering.

---

## Important Configuration Options

### similarityThreshold

Controls **retrieval quality**.

Only document chunks whose similarity score is greater than or equal to the threshold are included.

```text
Higher Threshold
        ↓
Better Quality
        ↓
Fewer Results
```

Typical values:

- 0.70 → Balanced
- 0.80 → High precision
- 0.90 → Very strict filtering

---

### topK

Controls **retrieval quantity**.

Even if many chunks satisfy the threshold, only the first **topK** chunks are passed to the LLM.

```text
Similarity Search
        ↓
15 Matching Chunks
        ↓
topK = 5
        ↓
Only 5 Chunks Reach the LLM
```

---

### Metadata Filtering

`filterExpression` limits retrieval to specific documents before similarity search begins.

Examples:

```text
country == 'India'

docType == 'policy'

country == 'India' && department == 'HR'
```

Filtering improves both retrieval accuracy and query performance because unrelated documents are excluded before vector comparison.

---

## Citations

One of the biggest advantages of `QuestionAnswerAdvisor` is that it remembers which document chunks were used to answer the question.

Retrieved documents are stored inside

```text
RETRIEVED_DOCUMENTS
```

From these documents the application can display:

- Source filename
- Page number
- Similarity score
- Text excerpt

This enables transparent and auditable AI responses.

---

## What QuestionAnswerAdvisor Cannot Do

Although powerful, the advisor has some limitations.

It cannot:

- Rewrite user queries before retrieval.
- Re-rank retrieved documents.
- Change the retrieval algorithm.
- Customize how retrieved context is formatted.
- Replace the VectorStore retrieval strategy.

## 🚀 Key Takeaways

- `QuestionAnswerAdvisor` is Spring AI's built-in Naive RAG implementation.
- It automatically performs retrieval and prompt augmentation.
- No manual RAG pipeline implementation is required.
- Default behaviour retrieves the Top 4 document chunks.
- `similarityThreshold` controls retrieval quality.
- `topK` limits the number of retrieved chunks.
- `filterExpression` restricts retrieval using document metadata.
- Retrieved source documents are stored in `RETRIEVED_DOCUMENTS`.
- Source metadata enables citations, traceability, and auditing.
- `QuestionAnswerAdvisor` greatly simplifies enterprise RAG development while reducing boilerplate code.
