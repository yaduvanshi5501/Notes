# 📝 Summary

`RetrievalAugmentationAdvisor` is Spring AI's **production-ready implementation of Modular RAG**. Unlike `QuestionAnswerAdvisor`, which provides a simple all-in-one RAG solution, `RetrievalAugmentationAdvisor` separates retrieval into configurable pipeline components. This modular design allows developers to customize every stage of retrieval, making it suitable for large-scale enterprise applications.

Instead of hardcoding retrieval logic, the advisor intercepts every ChatClient request, retrieves relevant documents, optionally transforms the query, optionally post-processes retrieved documents, augments the prompt, and finally sends the enriched prompt to the LLM.

---

# 🎯 Why RetrievalAugmentationAdvisor?

LLMs only know information available during training.

They cannot answer questions about:

- Company policies
- Internal documents
- Confidential data
- Recently created documents

Instead of retraining the model, Retrieval-Augmentation Generation (RAG) supplies the required information dynamically during every request.

```text
User Question
        ↓
Vector Search
        ↓
Relevant Documents
        ↓
Prompt Augmentation
        ↓
LLM
        ↓
Grounded Answer
```

The LLM remains unchanged while always receiving the latest business knowledge.

---

# ⚖️ QuestionAnswerAdvisor vs RetrievalAugmentationAdvisor

Although both advisors implement RAG, they target different use cases.

| QuestionAnswerAdvisor | RetrievalAugmentationAdvisor |
|-----------------------|------------------------------|
| Simple RAG | Modular RAG |
| Easy configuration | Highly configurable |
| Limited customization | Fully customizable |
| Best for demos | Best for production |
| Fixed retrieval pipeline | Configurable retrieval pipeline |
| Basic metadata support | Advanced filtering and processing |

As a rule:

- **QuestionAnswerAdvisor** → Learning and quick prototypes.
- **RetrievalAugmentationAdvisor** → Enterprise applications.

```text

(Optional)

        ↓

        ↓
Similarity Search
        ↓
(Optional)
Document Post Processing
        ↓
Prompt Augmentation
        ↓

        ↓

```

Each stage can be independently customized without changing the remaining pipeline.

# 📥 Document Retrieval

The advisor itself does not retrieve documents.

Instead, it delegates retrieval to a `DocumentRetriever`.

In this chapter the implementation used is

```text
VectorStoreDocumentRetriever
```

The retriever is responsible for

- generating query embeddings
- searching the VectorStore
- ranking similar chunks
- returning relevant documents

The advisor simply consumes these retrieved documents and augments the prompt.

---

# 📄 DOCUMENT_CONTEXT

After every successful request the advisor stores retrieved document chunks inside

```text
DOCUMENT_CONTEXT
```

Each document contains

- original text
- metadata
- filename
- page number
- similarity score

Unlike `QuestionAnswerAdvisor`, which exposes only retrieved documents, `RetrievalAugmentationAdvisor` provides complete document context, making it easier to build citations, debugging tools, and enterprise audit features.

---

# 🚫 Empty Context Handling

By default

```text
allowEmptyContext(false)
```

If no document satisfies the retrieval conditions, the advisor instructs the LLM not to answer.

```text
No Documents
        ↓
No Prompt Context
        ↓
LLM declines to answer
```

This prevents hallucinations in document-grounded applications.

When

```java
allowEmptyContext(true)
```

the advisor allows the LLM to answer using its pretrained knowledge whenever retrieval returns no matching documents.

This option should only be used when fallback answers are acceptable.

# 🔍 Metadata Filtering

Metadata filtering restricts retrieval before similarity search begins.

Instead of comparing every document, only matching documents participate.

Example

```text
country = India
```

Execution order

```text
All Documents
        ↓
Metadata Filter
        ↓
Matching Documents
        ↓
Similarity Search
        ↓
Threshold Check
        ↓
Top-K Selection
        ↓
Prompt Augmentation
```

Filtering improves both retrieval accuracy and search performance.

---

# ⚙️ Retrieval Configuration

The retriever provides three important controls.

### similarityThreshold

Controls retrieval quality.

Only chunks with similarity greater than or equal to the configured threshold are returned.

Higher threshold

- fewer documents
- higher precision

---

### topK

Controls retrieval quantity.

Limits the maximum number of retrieved chunks injected into the prompt.

---

### FilterExpressionBuilder

Builds metadata filters programmatically.

Example

```text
country == India
department == HR
version == 2025
```

Only matching documents participate in retrieval.

# 🚀 Key Takeaways

- `RetrievalAugmentationAdvisor` implements Modular RAG.
- It is designed for production-grade RAG systems.
- Retrieval is delegated to a configurable `DocumentRetriever`.
- `VectorStoreDocumentRetriever` performs semantic similarity search.
- Query transformation and document post-processing are optional pipeline stages.
- `DOCUMENT_CONTEXT` stores retrieved documents for citations and auditing.
- `allowEmptyContext(false)` prevents hallucinated responses.
- `allowEmptyContext(true)` enables fallback to the LLM's general knowledge.
- `similarityThreshold` controls retrieval quality.
- `topK` controls the number of retrieved chunks.
- `FilterExpressionBuilder` enables database-level metadata filtering.
- The modular pipeline makes `RetrievalAugmentationAdvisor` far more flexible than `QuestionAnswerAdvisor` for enterprise applications.
