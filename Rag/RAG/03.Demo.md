# 🚀 Demo Explanation

This demo implements a complete **Retrieval-Augmented Generation (RAG)** application using **Spring AI**, **OpenAI**, and a **MariaDB-backed VectorStore**. It demonstrates how enterprise documents can be transformed into vector embeddings and later retrieved using semantic similarity to generate accurate, context-aware responses.

Instead of relying solely on the Large Language Model's pretrained knowledge, the application first retrieves the most relevant information from the uploaded documents and then injects that information into the prompt before sending it to the LLM. This grounding process significantly reduces hallucinations and allows the model to answer using the organization's latest knowledge without requiring model retraining.

The demo is divided into **two major phases**: **Document Ingestion** and **Question Answering (Retrieval)**.

---

# 📥 Phase 1 – Document Ingestion

The first part of the demo focuses on preparing the knowledge base.

The application provides two ingestion APIs:

- **PDF Ingestion**
- **Text File Ingestion**

During ingestion, Spring AI reads the uploaded documents, converts them into `Document` objects, generates embeddings, and stores them inside the MariaDB VectorStore.

---

## 1. PDF Ingestion

Endpoint

```text
POST /api/rag/ingest-pdf
```

This endpoint accepts a PDF document uploaded by the user.

Example documents include:

- Employee handbook
- Company policy
- User manual
- Product guide
- HR document

Instead of storing the entire PDF as one large document, Spring AI uses **TokenTextSplitter** to divide the PDF into multiple semantic chunks.

Each chunk becomes an independent vector inside MariaDB.

For every chunk the application stores:

- Chunk text
- Embedding vector
- Source filename
- Document type (`pdf`)

This approach improves retrieval precision because only the relevant portions of a document are returned during search.

---

## 2. Text File Ingestion

Endpoint

```text
POST /api/rag/ingest-text
```

This endpoint demonstrates an alternative ingestion strategy.

Instead of splitting the document into chunks, the entire text document is stored as a single vector.

This helps compare the advantages and disadvantages of chunked versus non-chunked retrieval.

Metadata such as

- source
- type = text

is also stored alongside the embedding.

---

# 📤 Phase 2 – Question Answering

After documents have been ingested, users can ask natural language questions.

The application demonstrates **three different retrieval strategies**.

---

# 1️⃣ Simple Semantic Search

Endpoint

```text
GET /api/rag/ask-simple
```

Example

```text
What is the annual leave policy?
```

### What happens internally?

1. Spring AI converts the question into an embedding.
2. MariaDB compares the query vector with all stored vectors using cosine similarity.
3. The Top-K most relevant chunks are retrieved.
4. Retrieved chunks are combined into contextual information.
5. Context is injected into the prompt.
6. ChatClient sends the augmented prompt to the LLM.
7. The LLM generates a grounded answer.

No metadata filtering is applied in this scenario.

This demonstrates **pure semantic search**.

---

# 2️⃣ Hybrid Search

Endpoint

```text
GET /api/rag/ask-with-filter
```

Example

```text
Question

"What is the leave policy?"

Filter

type = pdf
```

This scenario combines

- Semantic Search
- Metadata Filtering

Instead of searching every document, MariaDB first applies the metadata filter.

Example

```text
type == "pdf"

or

source == "employee-handbook.pdf"
```

Only matching documents participate in similarity search.

Unlike Java-side filtering, the filtering happens **inside MariaDB**, making retrieval much faster and more efficient.

This approach is commonly used in enterprise systems for:

- Department-based search
- Customer-specific search
- Tenant isolation
- Source-based search
- Document-type filtering

---

# 3️⃣ Similarity Threshold Search

Endpoint

```text
GET /api/rag/ask-with-threshold
```

This scenario introduces another retrieval parameter:

```text
similarityThreshold
```

Instead of accepting every retrieved chunk, only chunks whose similarity score is greater than the configured threshold are returned.

Example

```text
Threshold = 0.80

0.91 ✅

0.86 ✅

0.74 ❌

0.62 ❌
```

This improves answer quality by removing weak or irrelevant matches.

The `topK` parameter is also configurable, allowing developers to control how many document chunks should be retrieved.

# 📂 RagController

```java
@RestController
@RequestMapping("/api/rag")
public class RagController {

    private final RagService ragService;

    @Value("classpath:rag-guide.txt")
    private Resource textFile;

    public RagController(RagService ragService) {
        this.ragService = ragService;
    }

    // Ingestion: Reads a PDF, chunks it, embeds the chunks and stores them in the VectorStore
    @PostMapping(value = "/ingest-pdf", consumes = "multipart/form-data")
    public ResponseEntity<String> ingestPdf(@RequestPart("file") MultipartFile file) {

        return ResponseEntity.ok(ragService.ingestPdfFile(file));
    }

    // Ingestion: Reads a text file and stores it without chunking
    @PostMapping("/ingest-text")
    public ResponseEntity<String> ingestText() {

        return ResponseEntity.ok(ragService.ingestText(textFile));
    }

    // RAG using only semantic similarity search
    @GetMapping("/ask-simple")
    public ResponseEntity<String> askSimpleQuestion(

            @RequestParam(defaultValue = "What is the top K parameter in RAG retrieval configuration?")
            String question) {

        return ResponseEntity.ok(ragService.askSimpleQuestion(question));
    }

    // Hybrid RAG = Semantic Search + Metadata Filter
    @GetMapping("/ask-with-filter")
    public ResponseEntity<String> askQuestionWithMetadataFilter(

            @RequestParam(defaultValue = "What is the process for applying for leave")
            String question,

            @RequestParam(defaultValue = "type")
            String filterKey,

            @RequestParam(defaultValue = "pdf")
            String filterValue) {

        return ResponseEntity.ok(
                ragService.askQuestionWithMetadataFilter(
                        question,
                        filterKey,
                        filterValue));
    }

    // Returns only documents whose similarity score is above the threshold
    @GetMapping("/ask-with-threshold")
    public ResponseEntity<String> askQuestionWithSimilarityThreshold(

            @RequestParam(defaultValue = "What are benefits of RAG?")
            String question,

            @RequestParam(defaultValue = "0.5")
            double similarityThreshold,

            @RequestParam(defaultValue = "3")
            int topK) {

        return ResponseEntity.ok(
                ragService.askQuestionWithSimilarityThreshold(
                        question,
                        similarityThreshold,
                        topK));
    }

}
```

```
package com.infy.rag.service;

import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;
import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.ai.document.Document;
import org.springframework.ai.reader.pdf.PagePdfDocumentReader;
import org.springframework.ai.reader.tika.TikaDocumentReader;
import org.springframework.ai.transformer.splitter.TextSplitter;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.core.io.Resource;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

@Service
public class RagService {

    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public RagService(ChatClient.Builder chatClientBuilder, VectorStore vectorStore) {
        this.chatClient = chatClientBuilder.build();
        this.vectorStore = vectorStore;
    }

    public String ingestPdfFile(MultipartFile file) {

        try {

            PagePdfDocumentReader pdfReader = new PagePdfDocumentReader(file.getResource());

            List<Document> documents = pdfReader.get();

            TextSplitter textSplitter = new TokenTextSplitter();

            List<Document> chunks = textSplitter.apply(documents);

            String fileName = file.getOriginalFilename();

            chunks.forEach(chunk -> {
                chunk.getMetadata().put("source", fileName);
                chunk.getMetadata().put("type", "pdf");
            });

            vectorStore.add(chunks);

            return "Successfully ingested " + chunks.size() + " document chunks from PDF: " + fileName;

        } catch (Exception e) {

            return "Error ingesting PDF: " + e.getMessage();
        }
    }

    public String ingestText(Resource textFile) {

        try {

            TikaDocumentReader reader = new TikaDocumentReader(textFile);

            List<Document> documents = reader.get();

            documents.forEach(doc -> {
                doc.getMetadata().put("source", textFile.getFilename());
                doc.getMetadata().put("type", "text");
            });

            vectorStore.add(documents);

            return "Successfully ingested "
                    + documents.size()
                    + " document(s) from text file: "
                    + textFile.getFilename();

        } catch (Exception e) {

            throw new RuntimeException("Failed to read guide content.", e);
        }
    }

    public String askSimpleQuestion(String question) {

        SearchRequest searchRequest = SearchRequest.builder()
                .query(question)
                .topK(3)
                .build();

        List<Document> relevantDocs = vectorStore.similaritySearch(searchRequest);

        StringBuilder context = new StringBuilder();

        for (Document doc : relevantDocs) {
            context.append(doc.getText()).append("\n\n");
        }

        String enrichedPrompt = String.format(
                "Given the context information and no prior knowledge, answer the query.\n\n"
                        + "Context:\n%s\n\n"
                        + "Question: %s\n\n"
                        + "Answer:",
                context.toString(),
                question);

        return chatClient.prompt(enrichedPrompt)
                .call()
                .content();
    }

    // Remaining methods...
}
```

# 🎯 One-Line Summary

- **PDF Ingestion** → Read → Chunk → Metadata → Embeddings → VectorStore
- **Text Ingestion** → Read → Metadata → Embeddings → VectorStore
- **Simple RAG** → Semantic Search → Prompt Augmentation → LLM Answer
- **Hybrid RAG** → Semantic Search + Metadata Filter → Prompt → LLM Answer
- **Threshold Search** → Similarity Threshold + Top-K → Prompt → LLM Answer
- **VectorStore** stores document embeddings for semantic retrieval.
- **ChatClient** generates the final answer using the retrieved context.
