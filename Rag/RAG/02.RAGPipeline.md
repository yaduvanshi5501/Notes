# 📝 Summary

Retrieval-Augmented Generation (RAG) follows a **two-phase architecture** that separates **knowledge preparation** from **question answering**.

### Phase 1 – Ingestion

Before users ask any questions, documents such as PDFs, text files, HTML pages, manuals, and policies are read into Spring AI as `Document` objects. These documents are then **chunked** into smaller semantic units using `TokenTextSplitter`, ensuring better retrieval accuracy, reduced token usage, and meaningful context preservation. Each chunk is converted into an **embedding** using an `EmbeddingModel` and stored in a **VectorStore** together with its original text and metadata. This follows the familiar **ETL (Extract → Transform → Load)** process:

```text
Read Documents
      ↓
Chunk Documents
      ↓
Generate Embeddings
      ↓
Store in VectorStore
```

---

### Phase 2 – Retrieval & Generation

Whenever a user submits a question, Spring AI automatically converts it into an embedding using the **same embedding model** used during ingestion. The VectorStore performs a **semantic similarity search**, optionally applying **metadata filters (`filterExpression`)** before ranking results and returning only the **Top-K** most relevant document chunks. These retrieved chunks are automatically injected into the prompt, allowing the `ChatModel` to generate responses grounded in the organization's knowledge instead of relying only on pretrained information.

```text
User Question
      ↓
EmbeddingModel
      ↓
VectorStore
      ↓
Top-K Relevant Chunks
      ↓
Prompt Augmentation
      ↓
ChatModel
      ↓
Final Answer
```

---

### Vector Store

A **VectorStore** is a specialized database designed to store **embeddings** instead of plain text. Unlike traditional databases that rely on exact keyword matching, it performs **semantic search**, retrieving documents based on meaning rather than identical words. Each stored record contains:

- Embedding Vector
- Original Text
- Metadata

Similarity is typically calculated using **Cosine Similarity**, enabling highly relevant document retrieval even when different words express the same meaning.

Popular Vector Stores include:

- PostgreSQL + pgvector
- Chroma
- MariaDB (used in this course)

---

## 🚀 Key Takeaways

- RAG consists of **Ingestion** and **Retrieval & Generation** phases.
- Documents are **read → chunked → embedded → stored** before users ask questions.
- The **same EmbeddingModel** must be used during ingestion and retrieval.
- `topK` controls how many relevant chunks are returned.
- `filterExpression` applies metadata filtering before similarity ranking.
- Spring AI automatically performs **prompt augmentation**.
- VectorStores enable **semantic search** instead of keyword matching.
- MariaDB with Vector Support is used as the VectorStore in this course.
- RAG produces accurate, grounded, and up-to-date responses while reducing hallucinations.
