# 📝 Summary

Metadata enrichment is an important preprocessing step in a Retrieval-Augmented Generation (RAG) pipeline that improves document retrieval by attaching AI-generated information to every document chunk before it is stored inside the VectorStore. While embeddings capture the semantic meaning of text, they do not always provide enough information to distinguish between multiple chunks that discuss similar topics. Metadata enrichment solves this limitation by adding structured information such as keywords and summaries, allowing the retriever to understand each chunk more accurately and return the most relevant information.

---

## Why Metadata Matters in RAG

Consider an HR policy document containing hundreds of pages. If an employee asks:

> "How many sick leave days can I carry forward?"

A traditional search system does not read the entire document every time. Instead, each section is already indexed with useful information such as:

- Keywords
- Summary
- Source
- Category

Example:

```text
Section

Sick Leave Policy

Keywords
→ sick leave
→ carry forward
→ encashment

Summary
→ Explains 12 days annual sick leave and
  carry-forward limit of 30 days.
```

Because every section already contains descriptive metadata, the search engine can immediately identify the correct section without scanning every page.

Spring AI follows the same idea in RAG.

Instead of storing only embeddings, it also stores AI-generated metadata that describes every document chunk.

---

## Problem Without Metadata

Suppose the following chunks are stored inside the VectorStore.

```text
Chunk A
"Sick leave: 12 days per year,
carry forward up to 30 days."

Chunk B
"Earned leave: 18 days per year,
carry forward up to 45 days."

Chunk C
"Casual leave: 7 days per year,
no carry forward."
```

Now the user asks:

```text
How many sick leave days can I carry forward?
```

The query embedding is compared against all stored embeddings.

Since every chunk contains similar words such as:

- leave
- days
- carry forward
- year

their similarity scores may be very close.

```text
Chunk A → 0.91

Chunk B → 0.89

Chunk C → 0.87
```

Without additional information, the retriever may return Chunk B even though Chunk A contains the correct answer.

This reduces retrieval accuracy.

---

## How Metadata Enrichment Solves This Problem

Instead of storing only:

```text
Document
↓

Embedding
```

Spring AI enriches every chunk before storage.

```text
Document
      ↓
TokenTextSplitter
      ↓
Metadata Enricher
      ↓
EmbeddingModel
      ↓
VectorStore
```

Each chunk now contains

- Original text
- Embedding
- Metadata

Example

```text
Text

"Sick leave: 12 days..."

Metadata

source = hr.pdf

excerpt_keywords =
sick leave,
carry forward,
12 days,
encashment

section_summary =
Explains sick leave entitlement
and carry-forward rules.
```

Now the retriever has additional semantic signals beyond vector similarity, producing much more accurate search results.

---

# Metadata Enricher

A **Metadata Enricher** is a Spring AI `DocumentTransformer`.

Its responsibility is to process every document chunk during the ingestion phase, call the Large Language Model once for each chunk, generate useful metadata, attach that metadata to the document, and return the enriched document before it is stored inside the VectorStore.

Unlike a normal transformer that changes the document text, a metadata enricher keeps the original content unchanged and only adds additional metadata.

Execution flow:

```text
DocumentReader
      ↓
TokenTextSplitter
      ↓
Metadata Enricher
      ↓
VectorStore
```

---

# Built-in Metadata Enrichers

Spring AI provides two built-in metadata enrichers.

| Enricher | Metadata Key | Purpose |
|----------|--------------|---------|
| KeywordMetadataEnricher | `excerpt_keywords` | Extract important keywords |
| SummaryMetadataEnricher | `section_summary` | Generate document summary |

Both implement the `DocumentTransformer` interface.

---

# KeywordMetadataEnricher

`KeywordMetadataEnricher` extracts the most important keywords from every document chunk.

Instead of manually writing tags for every document, Spring AI asks the LLM to generate them automatically.

Generated keywords are stored under

```text
excerpt_keywords
```

Example

```text
Chunk

Sick leave policy...

↓

Keywords

sick leave,
carry forward,
12 days,
encashment,
HR policy
```

---

## ETL Pipeline

```text
DocumentReader
      ↓
TokenTextSplitter
      ↓
KeywordMetadataEnricher
      ↓
VectorStore
```

Every chunk now contains

```text
Original Text

+

excerpt_keywords
```

---

## Internal Working

When

```java
.apply(chunks)
```

is executed, Spring AI performs the following steps internally.

```text
Loop through every chunk
        ↓
Read chunk text
        ↓
Build LLM prompt
        ↓
Send prompt using ChatModel
        ↓
Receive keywords
        ↓
Store keywords inside metadata
        ↓
Return enriched document
```

Internally Spring AI performs

```java
doc.getMetadata()
   .put("excerpt_keywords", llmResponse);
```

Later during retrieval, the metadata can be read using

```java
doc.getMetadata()
   .getOrDefault("excerpt_keywords","N/A");
```

---

# Why ChatModel Instead of ChatClient?

Metadata enrichment happens during document ingestion.

It is **not** a user conversation.

Therefore Spring AI uses **ChatModel** instead of **ChatClient**.

| ChatModel | ChatClient |
|-----------|------------|
| Low-level LLM interface | High-level conversational API |
| Single prompt → single response | Supports conversations |
| No advisors | Advisors supported |
| No memory | Conversation memory |
| Used during ingestion | Used during query time |

Since metadata generation is a one-time preprocessing task, `ChatModel` is the correct choice.

---

# SummaryMetadataEnricher

`SummaryMetadataEnricher` generates a concise summary for every document chunk.

Instead of extracting keywords, it produces a descriptive paragraph explaining what the chunk contains.

The generated summary is stored under

```text
section_summary
```

Example

```text
Chunk

Maternity Leave Policy...

↓

Summary

Explains maternity leave
eligibility,
duration,
and benefits.
```

---

## ETL Pipeline

```text
DocumentReader
      ↓
TokenTextSplitter
      ↓
SummaryMetadataEnricher
      ↓
VectorStore
```

---

## Internal Working

During

```java
.apply(chunks)
```

Spring AI performs

```text
Loop through chunks
        ↓
Read text
        ↓
Create summarization prompt
        ↓
Call ChatModel
        ↓
Receive summary
        ↓
Store section_summary
        ↓
Return enriched document
```

Internally

```java
doc.getMetadata()
   .put("section_summary", llmResponse);
```

During retrieval

```java
doc.getMetadata()
   .getOrDefault("section_summary","N/A");
```

returns the generated summary.

---

# SummaryType Options

`SummaryMetadataEnricher` supports multiple summarization strategies.

| SummaryType | Text Sent to LLM | Purpose |
|-------------|------------------|---------|
| CURRENT | Current chunk only | Independent summaries |
| PREVIOUS | Previous + Current | Uses previous context |
| NEXT | Current + Next | Looks ahead to the next section |

For independent document sections, **CURRENT** is usually the best option because every chunk can be summarized without relying on neighboring chunks.

---

# Complete Metadata Enrichment Workflow

```text
DocumentReader
        ↓
TokenTextSplitter
        ↓
Metadata Enricher
(Keyword / Summary)
        ↓
ChatModel
        ↓
Generate Metadata
        ↓
Attach Metadata
        ↓
EmbeddingModel
        ↓
VectorStore
```

Every stored document now contains:

- Original Text
- Embedding Vector
- Source Metadata
- AI-generated Keywords
- AI-generated Summary

This enriched information allows the VectorStore to retrieve more relevant document chunks, improves prompt construction, reduces ambiguity during retrieval, and ultimately helps the Large Language Model generate more accurate, grounded, and context-aware responses.

---

## 🚀 Key Takeaways

- Metadata enrichment improves retrieval quality by adding AI-generated information to every document chunk.
- A Metadata Enricher is a `DocumentTransformer` that runs during the ingestion phase.
- Spring AI provides `KeywordMetadataEnricher` and `SummaryMetadataEnricher`.
- `KeywordMetadataEnricher` stores extracted keywords in `excerpt_keywords`.
- `SummaryMetadataEnricher` stores generated summaries in `section_summary`.
- Both enrichers internally use `ChatModel` because metadata generation is a preprocessing task.
- `.apply(chunks)` automatically processes every document chunk and enriches its metadata.
- Metadata is stored together with embeddings inside the `VectorStore`.
- `SummaryType` controls how much surrounding context is provided during summarization.
- Combining embeddings with enriched metadata produces more accurate, reliable, and context-aware RAG responses while reducing ambiguity during retrieval.
