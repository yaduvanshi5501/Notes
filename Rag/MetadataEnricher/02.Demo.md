# 📝 Summary

This demo demonstrates how **Spring AI Metadata Enrichers** improve a Retrieval-Augmented Generation (RAG) system by enriching every document chunk with AI-generated metadata before it is stored inside the VectorStore. Instead of storing only embeddings, the application stores additional information such as **keywords** and **summaries**, enabling the retriever to build richer context and generate more accurate responses.

Unlike a traditional RAG application that relies only on semantic similarity, this project compares two metadata enrichment strategies provided by Spring AI—**KeywordMetadataEnricher** and **SummaryMetadataEnricher**—and also demonstrates how both can be combined into a hybrid retrieval approach.

---

## 📄 Document Ingestion Pipeline

The application begins by accepting a PDF document through the REST API. The uploaded PDF is read using `PagePdfDocumentReader`, which converts each page into Spring AI `Document` objects. Since large pages are not suitable for embedding directly, `TokenTextSplitter` divides every page into smaller semantic chunks.

```text
PDF
      ↓
PagePdfDocumentReader
      ↓
Document
      ↓
TokenTextSplitter
      ↓
Document Chunks
```

Each chunk is then processed individually before being stored inside the VectorStore.

---

## 🔑 Keyword Metadata Enrichment

The first enrichment strategy uses **KeywordMetadataEnricher**.

For every document chunk, Spring AI sends the text to the configured `ChatModel` and asks the LLM to extract the five most important keywords.

Example:

```text
Chunk

"Sick leave allows 12 days..."

↓

LLM

↓

Keywords

sick leave,
carry forward,
12 days,
HR policy,
encashment
```

These generated keywords are stored automatically inside the metadata map using the key

```text
excerpt_keywords
```

The application configures the enricher using

```java
KeywordMetadataEnricher.builder(chatModel)
        .keywordCount(5)
        .build();
```

During ingestion, calling

```java
keywordEnricher.apply(chunks)
```

automatically processes every document chunk, generates keywords through the LLM, and stores them inside the document metadata.

---

## 📄 Summary Metadata Enrichment

The second strategy uses **SummaryMetadataEnricher**.

Instead of extracting keywords, the LLM generates a concise paragraph describing the document chunk.

Example

```text
Chunk

Hotel Grand Heaven provides
a swimming pool and gym.

↓

Summary

Explains hotel amenities,
fitness centre,
pool facilities,
and guest services.
```

The generated summary is stored under

```text
section_summary
```

The application uses

```java
new SummaryMetadataEnricher(
        chatModel,
        List.of(SummaryType.CURRENT))
```

meaning only the current document chunk is summarized.

The enrichment process is executed by

```java
summaryEnricher.apply(chunks);
```

---

## ⚙️ Complete Ingestion Workflow

During PDF ingestion the coordinator service performs the following operations.

```text
Upload PDF
      ↓
PagePdfDocumentReader
      ↓
TokenTextSplitter
      ↓
KeywordMetadataEnricher
      ↓
SummaryMetadataEnricher
      ↓
EmbeddingModel
      ↓
MariaDB VectorStore
```

Every stored chunk finally contains

- Original text
- Embedding vector
- Source metadata
- `excerpt_keywords`
- `section_summary`

---

## 🗄️ MariaDB VectorStore

The application uses **MariaDB VectorStore** for storing embeddings.

During

```java
vectorStore.add(enrichedChunks);
```

Spring AI automatically

- Generates embeddings
- Stores vectors
- Saves metadata
- Persists original text

The embedding dimension is configured as **1536**, matching the `text-embedding-3-small` model.

Similarity calculations use **Cosine Similarity**.


This follows the same semantic retrieval process, but instead of keywords, it extracts

```text

```

from every retrieved document.

The summaries are inserted into the prompt, giving the LLM richer semantic context.

### Hybrid Search

```text
GET
/api/rag/search/hybrid
```

Hybrid search combines both metadata fields.

For every retrieved document the application reads

- `excerpt_keywords`
- `section_summary`

Workflow

```text

      ↓

      ↓

      ↓
```

This makes it easy to compare

- keyword-based retrieval
- summary-based retrieval

and evaluate which approach produces better responses.

## 🤖 ChatModel vs ChatClient

Both are used in this project for different responsibilities.

| Component | Responsibility |
|-----------|----------------|
| `ChatModel` | Used by metadata enrichers during ingestion to generate keywords and summaries |
| `ChatClient` | Used during retrieval to answer user questions using enriched metadata |

The enrichers require a low-level LLM interface because metadata generation is a one-time preprocessing task, while user interactions require the higher-level `ChatClient`.

## 🚀 Key Takeaways

- The project demonstrates metadata-enriched RAG using Spring AI.
- `PagePdfDocumentReader` reads PDF pages as `Document` objects.
- `TokenTextSplitter` divides documents into semantic chunks.
- `KeywordMetadataEnricher` generates and stores `excerpt_keywords`.
- `SummaryMetadataEnricher` generates and stores `section_summary`.
- Both enrichers internally use `ChatModel`.
- `VectorStore.add()` automatically generates embeddings and stores enriched documents.
- `KeywordMetadataEnricherService` answers questions using only keyword metadata.
- `SummaryMetadataEnricherService` answers questions using only summary metadata.
- `MetaDataEnricherService` supports hybrid retrieval and comparison of both enrichment strategies.
- `ChatClient` is used only during query time to generate the final grounded response.
- Combining keywords and summaries produces richer context and improves answer quality in enterprise RAG applications.

```java
package com.infy.rag.controller;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RequestPart;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;

import com.infy.rag.service.KeywordMetadataEnricherService;
import com.infy.rag.service.MetaDataEnricherService;
import com.infy.rag.service.SummaryMetadataEnricherService;

@RestController
@RequestMapping("/api/rag")
public class MetaDataEnricherController {

    private final KeywordMetadataEnricherService keywordService;
    private final SummaryMetadataEnricherService summaryService;
    private final MetaDataEnricherService coordinatorService;

    public MetaDataEnricherController(
            KeywordMetadataEnricherService keywordService,
            SummaryMetadataEnricherService summaryService,
            MetaDataEnricherService coordinatorService) {

        this.keywordService = keywordService;
        this.summaryService = summaryService;
        this.coordinatorService = coordinatorService;
    }

    // PDF Ingestion with both enrichers
    @PostMapping(value = "/ingest-pdf/both", consumes = "multipart/form-data")
    public ResponseEntity<String> ingestPdfWithBoth(
            @RequestPart("file") MultipartFile file) {

        return ResponseEntity.ok(
                coordinatorService.ingestPdfFileBoth(file));
    }

    // Search using Keyword Metadata
    @GetMapping("/search/keyword")
    public String searchByKeyword(

            @RequestParam(defaultValue =
                    "What amenities and services does Hotel Grand Heaven offer to guests?")
            String question) {

        return keywordService.searchDocumentByKeywords(question);
    }

    // Search using Summary Metadata
    @GetMapping("/search/summary")
    public String searchBySummary(

            @RequestParam(defaultValue =
                    "What are the check-in and check-out times at Hotel Grand Heaven?")
            String question) {

        return summaryService.searchDocumentBySummary(question);
    }

    // Hybrid Search (Keywords + Summary)
    @GetMapping("/search/hybrid")
    public String searchHybrid(

            @RequestParam(defaultValue =
                    "What is the cancellation policy at Hotel Grand Heaven?")
            String question) {

        return coordinatorService.searchDocumentHybrid(question);
    }

    // Compare Keyword Search and Summary Search
    @GetMapping("/search/compare")
    public String compareSearchMethods(

            @RequestParam(defaultValue =
                    "What are the pool and fitness center rules at Hotel Grand Heaven?")
            String question) {

        return coordinatorService.compareKeywordAndSummarySearch(question);
    }

}
```

# 📄 KeywordMetadataEnricherService

## 📌 Purpose

`KeywordMetadataEnricherService` demonstrates **Keyword-Based RAG**.

Instead of sending the complete document chunks to the LLM, it uses the
**`excerpt_keywords`** metadata generated during ingestion.

The retrieved keywords become the context for the LLM.

---

```text

│

│
│      User Question

│             ↓

│      Read "excerpt_keywords"
│             ↓

│      Prompt Augmentation
│             ↓
```

# Complete Code

```java
package com.infy.rag.service;

import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;
import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

@Service
public class KeywordMetadataEnricherService {

    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public KeywordMetadataEnricherService(
            ChatClient.Builder chatClientBuilder,
            VectorStore vectorStore) {

        this.chatClient = chatClientBuilder.build();
        this.vectorStore = vectorStore;
    }

    public String searchDocumentByKeywords(String question) {

        try {

            // Semantic Search
            List<Document> results = vectorStore.similaritySearch(
                    SearchRequest.builder()
                            .query(question)
                            .topK(3)
                            .build());

            if (results.isEmpty()) {
                return "No relevant documents found for: " + question;
            }

            // Build keyword context
            String keywordContext = results.stream()
                    .map(doc -> {

                        String keywords = (String) doc.getMetadata()
                                .getOrDefault("excerpt_keywords", "N/A");

                        return "📌 Keywords: " + keywords;

                    })
                    .collect(Collectors.joining("\n"));

            // Prompt Augmentation
            PromptTemplate promptTemplate = new PromptTemplate("""
                    Using ONLY these document keywords,
                    answer the question concisely.

                    {keywords}

                    Question:
                    {question}

                    Answer:
                    """);

            // Generate Answer
            String answer = chatClient
                    .prompt(promptTemplate.create(
                            Map.of(
                                    "keywords", keywordContext,
                                    "question", question)))
                    .advisors(SimpleLoggerAdvisor.builder()
                            .order(10)
                            .build())
                    .call()
                    .content();

            return """
                    ⚡ KEYWORD-BASED SEARCH

                    %s

                    ✅ Answer

                    %s
                    """.formatted(keywordContext, answer);

        } catch (Exception e) {

            return "Error in keyword search: " + e.getMessage();

        }

    }

}
```

|-----------|----------|
| `ChatClient` | Sends prompts to the LLM |
| `ChatModel` | Used by Metadata Enrichers |
| `VectorStore` | Stores and retrieves document embeddings |
| `KeywordMetadataEnricher` | Generates `excerpt_keywords` |
| `SummaryMetadataEnricher` | Generates `section_summary` |
| `TokenTextSplitter` | Splits documents into chunks |
| `SearchRequest` | Configures similarity search |
| `PromptTemplate` | Creates prompts for the LLM |

# Key Takeaways

- Applies **two metadata enrichers** during ingestion.
- Stores **`excerpt_keywords`** and **`section_summary`** in each document's metadata.
- Uses **Hybrid Search** by combining both metadata fields.
- Supports **comparison** between keyword-based and summary-based RAG.
- Demonstrates how Spring AI metadata enrichers improve retrieval quality without modifying the original document text.
