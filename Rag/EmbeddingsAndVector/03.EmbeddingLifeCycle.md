# 📚 Embedding Lifecycle in Spring AI (Ingestion & Search)

> **Objective:** Understand how Spring AI manages embeddings internally during document storage (ingestion) and semantic search. Learn how `EmbeddingModel` and `VectorStore` work together while remaining completely decoupled.

---

# 🎯 Learning Objectives

After completing this topic, you will understand:

- The two phases of embedding processing
- What happens during ingestion
- What happens during similarity search
- How `EmbeddingModel` and `VectorStore` interact
- Why developers usually work only with `VectorStore`
- Why Spring AI separates embedding generation from vector storage

---

# 🤔 Why Is This Important?

When developers first learn Spring AI, they often assume they must manually generate embeddings before storing documents.

For example:

```java
float[] vector = embeddingModel.embed("Spring AI supports RAG");
vectorStore.store(vector);
```

Fortunately, **Spring AI handles this entire workflow automatically**.

In most applications, you simply work with the `VectorStore`, and Spring AI coordinates embedding generation behind the scenes.

---

# The Two Phases of Embedding Processing

Spring AI manages embeddings in **two independent phases**.

```text
             Phase 1
        Document Storage
          (Ingestion)

               ↓

         Vector Database

               ↑

             Phase 2
       Similarity Search
          (Query Time)
```

---

# Phase 1 – Store Time (Ingestion)

## Purpose

Convert raw documents into embedding vectors and store them inside the vector database.

---

## Ingestion Flow

```text
Document

↓

EmbeddingModel

↓

Embedding Vector

↓

VectorStore

↓

Vector Database
```

Only the document is supplied by the developer.

Everything else happens automatically.

---

## Developer Code

The developer simply writes:

```java
Document document = new Document("Spring AI supports RAG");

vectorStore.add(List.of(document));
```

That's all.

No manual embedding generation is required.

---

# What Happens Internally?

Although only `vectorStore.add()` is called, Spring AI performs several operations behind the scenes.

### Step 1

Extract the document text.

```text
Spring AI supports RAG
```

↓

### Step 2

Generate an embedding using the configured `EmbeddingModel`.

```text
EmbeddingModel

↓

[0.003, 0.872, ...]
```

↓

### Step 3

Store both the vector and original document in the vector database.

Example:

```text
Document
```

```json
{
  "vector": [0.003, 0.872, ...],
  "content": "Spring AI supports RAG",
  "metadata": {
    ...
  }
}
```

The application never calls the `EmbeddingModel` directly.

Spring AI coordinates the entire ingestion process.

---

# Phase 2 – Search Time (Query)

## Purpose

Retrieve documents based on **meaning**, not exact keywords.

---

## Search Flow

```text
User Question

↓

EmbeddingModel

↓

Query Vector

↓

VectorStore

↓

Similarity Search

↓

Most Relevant Documents
```

---

## Developer Code

The developer simply performs a similarity search.

```java
List<Document> documents =
        vectorStore.similaritySearch(
                "How does Spring AI work?");
```

Again, no manual embedding generation is required.

---

# What Happens Internally?

Spring AI automatically performs the following steps.

### Step 1

Convert the user query into an embedding.

```text
How does Spring AI work?

↓

EmbeddingModel

↓

Query Vector
```

---

### Step 2

Compare the query vector with every stored vector.

```text
Query Vector

↓

Stored Vector A

Stored Vector B

Stored Vector C
```

Similarity is usually measured using **Cosine Similarity**.

---

### Step 3

Rank documents by similarity score.

Example:

| Document               | Similarity Score |
| ---------------------- | ---------------: |
| Spring AI supports RAG |             0.95 |
| Spring AI Chat Memory  |             0.88 |
| Order Pizza            |             0.09 |

---

### Step 4

Return the most relevant documents.

```text
Top Matching Documents

↓

Application
```

---

# Why Doesn't the Developer Call `EmbeddingModel`?

This is one of Spring AI's biggest design advantages.

Instead of writing:

```java
EmbeddingModel

↓

VectorStore
```

Developers simply use:

```java
VectorStore
```

Spring AI internally invokes the configured `EmbeddingModel` whenever embeddings are required.

This greatly simplifies application development.

Embedding Provider

The `VectorStore` orchestrates embedding generation and storage transparently.

# Why Separate `EmbeddingModel` and `VectorStore`?

Spring AI intentionally separates these responsibilities.

| Component        | Responsibility                                  |
| ---------------- | ----------------------------------------------- |
| `EmbeddingModel` | Convert text into embedding vectors (`float[]`) |
| `VectorStore`    | Store vectors and perform similarity search     |

This separation provides flexibility.

---

# Benefits of Decoupling

Because the two components are independent, either one can be replaced without affecting the other.

For example:

### Change Embedding Provider

```text
OpenAI

↓

Ollama
```

No changes are required to the vector store.

---

### Change Vector Database

```text
MariaDB

↓

Pinecone
```

No changes are required to the embedding model.

---

# Best Practices

- Let `VectorStore` manage embedding generation automatically.
- Do not manually generate embeddings unless your application has a specific requirement.
- Keep `EmbeddingModel` and `VectorStore` independent.
- Choose an embedding model appropriate for your domain.
- Choose a vector store that fits your scalability and performance requirements.

# 📝 Quick Revision

- Spring AI manages embeddings in two phases: **Ingestion** and **Search**.
- During ingestion, documents are converted into embeddings and stored.
- During search, user queries are converted into embeddings.
- `VectorStore` automatically invokes `EmbeddingModel`.
- Developers typically interact only with `VectorStore`.
- `EmbeddingModel` generates vectors.
- `VectorStore` stores vectors and performs similarity search.
- The two components are intentionally decoupled for flexibility.

---

# 🔥 Summary

Spring AI manages embeddings through two lifecycle phases: **Ingestion**, where documents are converted into embedding vectors and stored, and **Search**, where user queries are transformed into embeddings and compared with stored vectors to find semantically similar documents. Developers interact only with the `VectorStore`, while Spring AI transparently delegates embedding generation to the configured `EmbeddingModel`. By separating embedding generation from vector storage, Spring AI allows applications to switch embedding providers or vector databases independently, making AI applications more modular, portable, and easier to maintain.
