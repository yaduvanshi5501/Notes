## GitHub Models – Why Per-Minute Limits Matter

When using **GitHub Models**, every API request counts against your allocated quota. Although GitHub Models provide free access to several AI models, they enforce request limits to ensure fair usage across all users.

Because of these limits, applications must control how frequently they call the API, especially during operations such as embedding generation, document ingestion, or Retrieval-Augmented Generation (RAG).

---

### Typical Limits

GitHub Models commonly enforce limits such as:

- Approximately **10–15 requests per minute (RPM)** (depending on the model and current policy)
- Daily request quotas
- Limits on concurrent requests

> **Note:** These limits may change over time. Always refer to the official GitHub Models documentation for the latest quotas.

---

## Why Per-Minute Limits Matter

### 1. Prevent HTTP 429 Errors

If your application sends requests faster than the permitted rate, GitHub Models immediately rejects additional requests.

```text
Application

↓

Too Many Requests

↓

HTTP 429
```

This interrupts document ingestion, embedding generation, or chat requests.

---

### 2. Avoid Retry Storms

Many applications automatically retry failed requests.

Example:

```text
1 Request

↓

429 Error

↓

Retry

↓

Retry Again
```

A single failed request can quickly become multiple API calls, consuming even more of the available quota and making the problem worse.

---

### 3. Support Multiple Users

Rate limits are generally enforced per API key.

```text
User A

↓

GitHub API Key

↑

User B

↑

User C
```

As more users share the same API key, the available request quota is consumed more quickly.

---

### 4. Maintain Stable Performance

A controlled request rate keeps the application responsive.

```text
Controlled Requests

↓

Consistent AI Responses
```

Large bursts of traffic may trigger throttling, increased latency, or temporary request failures.

---

### 5. Use Your Quota Efficiently

Every request consumes provider resources, including:

- Request quota
- Token quota
- Daily usage allowance

Reducing unnecessary requests allows your application to serve more users before reaching its limits.

---

## Best Practices

- Keep request rates below the provider's maximum limit.
- Use a **RateLimiter** (such as Resilience4j) instead of manually delaying requests.
- Avoid sending large numbers of parallel requests.
- Use retries with exponential backoff rather than immediate retries.
- Batch requests where possible.
- Use smaller prompts and lighter models when appropriate.
- Monitor API usage and quota consumption.

---

## ✅ Key Takeaway

GitHub Models enforce **per-minute**, **daily**, and **concurrent request** limits. Even if your application sends relatively few requests per second, exceeding the allowed requests within a one-minute window can still result in **HTTP 429 (Too Many Requests)** errors. Using a RateLimiter helps ensure stable performance, efficient quota usage, and reliable AI-powered applications.
