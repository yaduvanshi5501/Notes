# 🤔 Why Do We Need Embeddings?

Traditional search relies on matching words.

Example:

User searches:

```text
How do I reset my password?
```

Document title:

```text
Account Recovery Steps
```

Although both mean the same thing, keyword search may fail because none of the important words match exactly.

---

## Traditional Search

```text
User Query

↓

Keyword Matching

↓

No Exact Match

↓

No Result
```

The search engine only compares words, not meaning.

---

# The Solution: Embeddings

Embeddings allow applications to understand **meaning** instead of matching exact words.

Now the same search becomes:

```text
User Query

↓

Embedding

↓

Semantic Comparison

↓

Account Recovery Steps
```

Even though the wording is different, the application understands both sentences describe the same concept.

---

# What Are Embeddings?

An **embedding** is a numerical representation of data that captures its meaning.

Instead of storing text as words, the text is represented as a vector of floating-point numbers.

Example:

```text
Reset password

↓

[0.021, -0.034, 0.071, ..., 0.015]
```

Another sentence:

```text
Account recovery steps

↓

[0.019, -0.031, 0.068, ..., 0.017]
```

Notice that the vectors are very similar because the meanings are similar.

---

# In Simple Words

Think of an embedding as the **GPS location of meaning**.

Two texts with similar meanings are located close together.

Example:

```text
Reset password

        ●

Account recovery

        ●

Best pizza

                           ●
```

The first two are close.

The pizza example is far away because it is unrelated.

# Important Concepts

## Vector

A vector is simply an array of floating-point numbers.

Example:

```text
[0.012, -0.045, 0.078, ..., -0.021]
```

Each number represents one dimension of the embedding.

---

## Dimensionality

Dimensionality is the number of values inside the vector.

Example:

| Model | Dimensions |
|--------|-----------:|
| text-embedding-3-small | 1536 |
| text-embedding-3-large | 3072 |
| mxbai-embed-large | 1024 |

Higher dimensions usually capture more semantic information but require more storage and computation.

---

## Similarity

Embeddings are useful because similar texts produce similar vectors.

Example:

```text
Reset password

↓

Vector A
```

```text
Recover account

↓

Vector B
```

Vector A and Vector B are close together.

---

## Vector Store

A Vector Store is a specialized database designed to store vectors and perform similarity search.

Each record contains:

- Original text
- Embedding vector
- Optional metadata

Example:

| Original Text | Vector |
|---------------|--------|
| Reset password | [0.021, ...] |
| Account recovery | [0.019, ...] |
| Order pizza | [0.891, ...] |

# How Embeddings Are Created

Generating embeddings involves three major steps.

---

## Step 1 – Tokenization

The sentence is split into tokens.

Example:

```text
Spring AI is great

↓

["Spring", "AI", "is", "great"]
```

Tokens may be:

- Words
- Parts of words
- Characters

depending on the model.

---

## Step 2 – Embedding Model

The embedding model processes all tokens together.

It considers:

- Word meanings
- Context
- Word order
- Relationships between words

Example:

```text
Dog bites man

≠

Man bites dog
```

Different order results in different embeddings.

---

## Step 3 – Vector Generation

The model converts the sentence into one fixed-length vector.

Example:

```text
Spring AI is great

↓

[0.012, -0.045, ..., -0.021]
```

Whether the sentence contains:

- 3 words
- 30 words
- 300 words

the vector always has the same dimension for a given embedding model.

---

# What Do the Numbers Mean?

Each individual number has no human-readable meaning.

Meaning is represented by the **combination** of all dimensions.

Think of it like GPS coordinates.

Example:

```text
Latitude

+

Longitude

↓

New York
```

Similarly,

```text
1536 Numbers

↓

Meaning of the Text
```

---

# The Ingestion Pipeline

Before documents can be searched semantically, they must first be converted into embeddings.

This process is called **ingestion**.

---

# Ingestion Steps

```text
Raw Documents

↓

Extract Text

↓

Embedding Model

↓

Vector

↓

Vector Store
```

The process usually runs once when documents are added or updated.

---

# What Is Stored?

Each document is stored together with its vector.

```text
Document

↓

Embedding

↓

Metadata

↓

Vector Store
```

Later, only the vectors are compared during search.

# Vector Dimensionality

Different embedding models produce vectors of different sizes.

Examples:

| Model | Dimensions |
|--------|-----------:|
| text-embedding-ada-002 | 1536 |
| text-embedding-3-small | 1536 |
| text-embedding-3-large | 3072 |
| mxbai-embed-large | 1024 |

**Important:** The vector store schema must match the embedding model's dimensions exactly. If the dimensions do not match, vector insertion and similarity search will fail.

---

# Similarity Search

Once embeddings are generated, we compare vectors to determine semantic similarity.

The most common method is:

```text
Cosine Similarity
```

---

# What Is Cosine Similarity?

Cosine similarity measures the angle between two vectors.

It ignores vector length and focuses only on direction.

Smaller angle:

```text
Similar Meaning
```

Larger angle:

```text
Different Meaning
```

---

# Cosine Similarity Values

| Score | Meaning |
|--------|---------|
| 1.0 | Identical meaning |
| 0.8 – 0.99 | Very similar |
| 0.5 – 0.79 | Somewhat related |
| 0.0 | Unrelated |
| -1.0 | Opposite meaning |

---

# Example

Query:

```text
How do I reset my password?
```

Stored documents:

```text
Account recovery

Reset password

Order pizza
```

Similarity scores:

```text
Account recovery

0.95
```

```text
Reset password

0.88
```

```text
Order pizza

0.12
```

The highest score wins.

---

# Why Cosine Similarity?

Two common methods exist.

| Method | Limitation |
|----------|------------|
| Euclidean Distance | Influenced by vector length |
| Cosine Similarity | Compares only semantic direction |

Cosine similarity works better because long and short documents about the same topic remain highly similar.

# How Spring AI Uses Embeddings

Spring AI separates responsibilities:

| Component | Responsibility |
|------------|----------------|
| EmbeddingModel | Generate vectors |
| VectorStore | Store vectors |
| Similarity Search | Find related vectors |
| ChatClient | Uses retrieved documents in RAG |

This abstraction allows developers to switch embedding providers without changing business logic.

---

# Best Practices

- Choose an embedding model appropriate for your use case.
- Ensure the vector store schema matches the embedding dimension.
- Use persistent vector stores in production.
- Perform ingestion only when documents are added or updated.
- Use cosine similarity for semantic search.
- Store useful metadata alongside embeddings for filtering and retrieval.

# 🔥 Summary

Embeddings are numerical vector representations of text that capture semantic meaning rather than exact words. They form the foundation of semantic search, recommendation systems, Retrieval-Augmented Generation (RAG), and many modern AI applications. During ingestion, documents are converted into fixed-size vectors using an `EmbeddingModel` and stored in a `VectorStore` along with their metadata. At query time, the user's query is also converted into an embedding, and similarity algorithms such as cosine similarity identify the most semantically relevant documents. Spring AI simplifies this entire workflow through abstractions like `EmbeddingModel` and `VectorStore`, allowing developers to switch providers while keeping application code unchanged.
