# 📝 Summary

This demo demonstrates how to build a **Modular Retrieval-Augmented Generation (RAG)** application using Spring AI's `RetrievalAugmentationAdvisor`. Unlike the previous demo that focused on a basic retrieval pipeline, this project showcases how different RAG modules can be independently plugged into the advisor to improve retrieval quality before documents reach the LLM.

The application ingests hotel policy PDFs, stores their embeddings inside a MariaDB VectorStore, and then demonstrates different Modular RAG components including **Query Rewrite, Query Compression, Query Translation, Multi-Query Expansion, and Contextual Query Augmentation**.

---

# 🏗️ Overall Architecture

The application consists of two phases.

1. **Document Ingestion**

# 📥 Document Ingestion

The `/ingest-pdf` endpoint prepares the knowledge base.

```text
      ↓
```

After ingestion, the documents are ready for semantic retrieval.

After retrieval, the application uses

It also demonstrates


---

# 🔧 chatClient.mutate()

Every query transformation module uses

```java
chatClient.mutate()
```

to create an isolated ChatClient.

This prevents internal LLM calls made by transformers from inheriting advisors configured for the main conversation.

Without `mutate()`, components such as chat memory or logging advisors could interfere with the transformer's internal prompt.

# 🚀 Key Takeaways

- The project demonstrates Spring AI's Modular RAG architecture using `RetrievalAugmentationAdvisor`.
- PDFs are ingested using `PagePdfDocumentReader` and stored as vector embeddings.
- `RewriteQueryTransformer` rewrites ambiguous or verbose queries before retrieval.
- `CompressionQueryTransformer` converts conversation history into standalone search queries.
- `TranslationQueryTransformer` translates multilingual questions into the embedding language.
- `MultiQueryExpander` generates multiple semantic query variations to improve retrieval recall.
- `VectorStoreDocumentRetriever` performs semantic similarity search over stored embeddings.
- `ContextualQueryAugmenter` combines retrieved context with the user question before sending it to the LLM.
- `allowEmptyContext(false)` prevents hallucinations by refusing to answer without supporting documents.
- `allowEmptyContext(true)` allows fallback to the model's own knowledge when retrieval returns no context.
- All pre-retrieval modules use `chatClient.mutate()` to isolate their internal LLM calls from the main advisor pipeline.
- The modular design allows each stage of the RAG pipeline to be independently replaced or extended without changing the rest of the application.

# Controller Code

```java
package com.infy.rag.controller;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import com.infy.rag.model.RagModuleResponse;
import com.infy.rag.service.RAAModulesService;

@RestController
@RequestMapping("/rag-advisor")
public class RAAModulesController {

    private final RAAModulesService raAdvisorService;

    public RAAModulesController(
            RAAModulesService raAdvisorService) {

        this.raAdvisorService = raAdvisorService;
    }

    @PostMapping("/ingest-pdf")
    public ResponseEntity<String> loadData() {

        return ResponseEntity.ok(
                raAdvisorService.loadCorpus());
    }

    @GetMapping("/query-rewrite")
    public ResponseEntity<RagModuleResponse> answerWithQueryRewrite(

            @RequestParam(defaultValue =
                    "I am planning to book a room along with my pet and elderly parents. What special services and amenities are available at the hotel premises?")
            String question) {

        return ResponseEntity.ok(
                raAdvisorService.answerWithQueryRewrite(question));

    }

    @PostMapping("/query-compression")
    public ResponseEntity<RagModuleResponse> answerWithQueryCompression(

            @RequestParam(defaultValue =
                    "What is the cancellation fee if I cancel my hotel booking 3 days before check in?")
            String question,

            @RequestParam(defaultValue = "user1")
            String conversationId) {

        return ResponseEntity.ok(
                raAdvisorService.answerWithQueryCompression(
                        question,
                        conversationId));

    }

    @GetMapping("/retrieve-with-translation")
    public RagModuleResponse answerWithQueryTranslation(

            @RequestParam(defaultValue =
                    "क्या होटल में पालतू जानवरों की अनुमति है?")
            String question) {

        return raAdvisorService.answerWithQueryTranslation(
                question);

    }

    @GetMapping("/retrieve-with-expansion")
    public RagModuleResponse retrieveWithMultiQueryExpansion(

            @RequestParam(defaultValue =
                    "What is the refund timeline for cancellations in France?")
            String question) {

        return raAdvisorService.retrieveWithMultiQueryExpansion(
                question);

    }

    @GetMapping("/retrieve-with-contextual-augmentation")
    public RagModuleResponse retrieveWithContextualQueryAugmentation(

            @RequestParam(defaultValue =
                    "How can I dispute a billing issue?")
            String question,

            @RequestParam(defaultValue = "false")
            boolean allowEmptyContext) {

        return raAdvisorService.answerWithContextualAugmenter(
                question,
                allowEmptyContext);

    }

}
```

# 📄 Query Transformers (Pre-Retrieval Modules)

## 📌 Overview

Query Transformers are **Pre-Retrieval** modules in Spring AI Modular RAG.

They modify the user's question **before** searching the VectorStore.

Instead of retrieving documents using the original query, the transformed query is used, improving retrieval quality.

Spring AI provides three built-in Query Transformers:

- **RewriteQueryTransformer**
- **CompressionQueryTransformer**
- **TranslationQueryTransformer**

Before any query transformation works, documents must be stored in the VectorStore.

```text
      ▼
```

---

## Code

```java
@RateLimiter(name = "embeddingLimiter")
public String loadCorpus() {

    List<Document> allDocs = new ArrayList<>();

    for (Resource pdf : pdfs) {

        PagePdfDocumentReader reader =
                new PagePdfDocumentReader(pdf);

        List<Document> docs = reader.get();

        for (Document d : docs) {
            d.getMetadata().put("source", pdf.getFilename());
        }

        allDocs.addAll(docs);
    }

    TextSplitter splitter =
            new TokenTextSplitter(true);

    List<Document> chunks =
            splitter.apply(allDocs);

    vectorStore.add(chunks);

    return "Successfully ingested "
            + chunks.size()
            + " document chunks.";

}
```

# 📄 MultiQueryExpander (Pre-Retrieval Module)

## 📌 Overview

`MultiQueryExpander` is a **Pre-Retrieval** component in Spring AI Modular RAG.

Instead of searching the VectorStore using a single question, it generates **multiple semantically different versions** of the same question.

Each query is searched independently, and the retrieved documents are combined before sending them to the LLM.

This significantly improves **Recall** (finding more relevant documents).

---

# Why Do We Need MultiQueryExpander?

A user may ask the same question in many different ways.

Example:

```text
Original Question

↓

What is the refund timeline
for cancellations in France?
```

Some documents may use different wording like:

```text
Refund Policy

Cancellation Refund

Money Back Policy

Booking Refund

Cancellation Processing Time
```

A single query may miss some of these documents.

MultiQueryExpander solves this problem.

# Key Takeaways

- `MultiQueryExpander` is a **Pre-Retrieval** module that generates multiple semantically equivalent queries.
- Each expanded query searches the `VectorStore`, and the results are combined before prompt augmentation.
- It improves **recall** by finding documents that may use different wording, synonyms, or alternative phrases.
- `includeOriginal(true)` ensures the original query is searched along with the expanded versions.
- `numberOfQueries(3)` controls how many additional queries are generated.
- This approach is especially useful when the same concept can be expressed in multiple ways, increasing the likelihood of retrieving the most relevant documents. :contentReference[oaicite:0]{index=0}

# 📄 ContextualQueryAugmenter (Generation Module)

## 📌 Overview

`ContextualQueryAugmenter` is a **Generation** module in Spring AI Modular RAG.

Unlike **Query Transformers** and **Query Expanders**, which work **before retrieval**, the `ContextualQueryAugmenter` works **after document retrieval**.

Its responsibility is to build a **clean, compact, and grounded context** for the LLM using the retrieved documents.

Instead of sending raw document chunks, it prepares a better prompt for the model.

# Key Takeaways

- `ContextualQueryAugmenter` is a **Generation** module that runs **after document retrieval**.
- It formats and organizes the retrieved context before it is sent to the LLM, producing cleaner and more grounded prompts.
- `allowEmptyContext(false)` keeps responses strictly grounded in retrieved documents and refuses to answer when no relevant context exists.
- `allowEmptyContext(true)` allows the LLM to fall back to its own general knowledge if retrieval returns no matching documents.
- Unlike `QueryTransformer` (which modifies the query), `ContextualQueryAugmenter` modifies the **retrieved context**, improving answer quality without changing retrieval behavior. :contentReference[oaicite:0]{index=0}

# Key Takeaways

- `RetrievalAugmentationAdvisor` is the central orchestrator of **Modular RAG**, coordinating each stage of the retrieval pipeline.
- `RAAModulesService` demonstrates how pre-retrieval modules (query transformers and expanders), the retrieval module (`VectorStoreDocumentRetriever`), and the generation module (`ContextualQueryAugmenter`) can be combined independently.
- `MessageWindowChatMemory` retains only the most recent three messages, providing conversational context while limiting memory growth.
- The project uses **GitHub Models** (`GPT-4.1` for generation and `text-embedding-3-small` for embeddings) with a **MariaDB Vector Store** configured for cosine similarity and 1536-dimensional vectors.
- Modular RAG provides much greater flexibility than `QuestionAnswerAdvisor`, making it suitable for production applications where retrieval strategies and generation behavior may evolve independently. :contentReference[oaicite:0]{index=0}
